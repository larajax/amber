File Upload ​

The fileupload field uploads files to an attachOne or attachMany relation, by clicking Upload or dropping files on the field. Each upload becomes a file record attached through the relation, so the field writes nothing to the model's own columns.

How files are stored ​

The field name is the name of a file attachment relation on the model. $attachOne holds one file and $attachMany a list, each pointing at a File model. The examples on this page use these relations:

php
/**
 * @var array<string, mixed> attachOne relations, where the contract is stored privately.
 */
public $attachOne = [
    'cover' => File::class,
    'brochure' => File::class,
    'contract' => [File::class, 'public' => false],
];

/**
 * @var array<string, mixed> attachMany relations
 */
public $attachMany = [
    'gallery' => File::class,
    'attachments' => File::class,
    'documents' => File::class,
];

Uploads use deferred binding. A new upload is stored as a file record straight away, but it is attached against the form's session key rather than to the record, and removing a file waits the same way. The changes take effect when the record is saved with that session key, so leaving the page without saving drops them, and a record that does not exist yet can still take uploads. The form posts its key as _session_key, and Building a Form Page shows how to pass it when saving.

Attachments and deferred binding come from October Rain models, so the field needs a model that extends October\Rain\Database\Model. Models covers the File model and the differences from plain Eloquent.

Single image ​

mode: image shows the file as a thumbnail. On an attachOne relation the field holds one image, and a new upload replaces it. imageWidth and imageHeight set the thumbnail size in pixels, and the thumbnail is made at that size on the server. Without fileTypes, image mode accepts jpg, jpeg, bmp, png, webp, avif and gif.

yaml
fields:
    cover:
        label: Cover Image
        type: fileupload
        mode: image
        imageWidth: 260
        imageHeight: 160
        comment: One image, with its thumbnail made at 260 by 160.

Multiple images ​

On an attachMany relation the field lists every image in a grid. Drag the handle to sort them, and the new order is written straight away. Check several images to delete them together.

maxFiles caps how many files the field takes. fileTypes limits the extensions, as a comma separated list. thumbOptions passes resize options to the thumbnails: mode is one of auto (the default), exact, portrait, landscape, fit, cover or crop, and extension: auto keeps each image's own format. Here crop cuts every image to a square.

yaml
fields:
    gallery:
        label: Gallery
        type: fileupload
        mode: image
        imageWidth: 120
        imageHeight: 120
        maxFiles: 6
        fileTypes: jpg,jpeg,png,gif,webp
        thumbOptions:
            mode: crop
            extension: auto
        comment: Up to six images, cropped into square thumbnails.

Single file ​

mode: file lists the file by its name and size instead of a thumbnail. fileTypes checks the extension of the file name, and mimeTypes also checks the type of the content, so a file renamed to .pdf is refused. maxFilesize sets the largest file in megabytes. It defaults to PHP's upload limit, and the field throws an error when it is set higher than that limit.

yaml
fields:
    brochure:
        label: Brochure
        type: fileupload
        mode: file
        fileTypes: pdf
        mimeTypes: pdf
        maxFilesize: 2
        comment: One PDF file, checked by extension and MIME type, up to 2 MB.

Without fileTypes, file mode accepts a broad default set of documents, images, audio, video, fonts and archives. The media.default_extensions and media.image_extensions config keys change the two default sets.

Multiple files ​

On an attachMany relation in file mode, each file has a checkbox and a drag handle. size sets how tall the list grows before it scrolls: tiny (100 pixels), small (200), large (400, the default), huge (500) or giant (700).

yaml
fields:
    attachments:
        label: Attachments
        type: fileupload
        mode: file
        maxFiles: 5
        size: small
        comment: Up to five files of the default types, in a list that scrolls past 200 pixels.

Private files ​

The field follows the relation, and the YAML needs nothing extra. 'public' => false on the relation stores each upload as a private file, in the File model's protected folder instead of its public one. Where those folders live, and how a private file is served, is up to the File model.

yaml
fields:
    contract:
        label: Contract
        type: fileupload
        mode: file
        comment: Stored in the protected uploads folder, since the relation sets public to false.

Attach on upload ​

deferredBinding: false attaches each upload to the record as soon as it finishes, without waiting for Save. This only applies to a saved record, since a new one has nothing to attach to yet, and removing a file still waits for Save.

yaml
fields:
    documents:
        label: Documents
        type: fileupload
        mode: file
        deferredBinding: false
        comment: Attached to the sample as soon as the upload finishes, without waiting for Save.

Preview ​

disabled puts the field in preview mode: the files show without the toolbar, the checkboxes or the drag handles, and the upload handlers refuse requests. With no files, the field says so. This copy reads the gallery through valueFrom.

yaml
fields:
    gallery_preview:
        label: Gallery
        type: fileupload
        mode: image
        valueFrom: gallery
        disabled: true
        imageWidth: 120
        imageHeight: 120
        thumbOptions:
            mode: crop
            extension: auto
        comment: Shows the gallery without its toolbar, and says so when there are no files.

Options ​

OptionDescription
modeimage for thumbnails or file for a list of names. The relation picks single or multiple, or name both, such as image-multi. Default: image.
imageWidththe thumbnail width in pixels. Default: 190.
imageHeightthe thumbnail height in pixels. Default: 190.
thumbOptionsresize options for the thumbnails, such as mode, extension and quality, or false to show the original images. Default: mode: auto and extension: auto.
fileTypesthe accepted extensions, as a comma separated list, or * for any. Default: the image set in image mode, the default set in file mode.
mimeTypesthe accepted content types, as a comma separated list of extensions, checked against the type read from the uploaded content. Default: no check.
maxFilesizethe largest file in megabytes, which cannot exceed PHP's upload limit. Default: PHP's upload limit.
maxFilesthe most files the field takes. Default: no limit.
deferredBindingattaches uploads against the session key until the record is saved. false attaches them to a saved record straight away. Default: true.
sizein multiple mode, how tall the list grows before it scrolls: tiny, small, large, huge or giant. Default: large.

The field also takes the common field properties, such as disabled and valueFrom.
