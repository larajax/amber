Custom Widgets ​

Your app can add its own widgets beside the built-in ones. A widget is a PHP class with its own partials, any number of AJAX handlers, and a script and stylesheet that load only on the pages that render it. There are three kinds, and this page builds one of each:

  • A form widget is a field type. A form creates it for any field that names it as its type. The first is a time checker that compares the browser clock with the server clock, and the page walks through each of its files.
  • A standalone widget is a part of a page that a controller builds itself, the way it builds a list or a form. The second is a feed of a post's comments, see a standalone widget.
  • A list widget is a column type. A list creates it for any column that names it as its type. The third is a meter that draws a number as a bar, see a list widget.

When a screen needs something the built-in fields and widgets do not cover, build it as one of these rather than as markup and script in a view. The widget carries its handlers and assets with it, so it works on every page that uses it.

The time checker widget ​

The widget shows the browser clock ticking, and a button that asks the server for its time. Checking runs the widget's own onCheckTime handler, which stamps the server time into the field and shows how far the two clocks drift apart. Saving the form stores the stamp like any other field.

A field uses the widget by naming its code as the type, and passes options beside it, here the format the stamp is shown in:

yaml
fields:
    checked_at:
        label: Server Time Check
        type: timechecker
        format: D j M Y, H:i:s T
        comment: Checking stamps the server time into this field, and Save stores it.

The widget class ​

A form widget extends Larajax\Ui\Classes\FormWidgetBase. The form creates it for the field, then calls these methods:

  • init() runs once the widget is created. fillFromConfig() copies options from the field's configuration onto the public properties of the same name, here format, keeping the property's value as the default.
  • render() returns the widget's markup, usually from a partial.
  • getSaveValue($value) receives the posted value when the form saves, and returns the value to store. Here an empty stamp is stored as null. When the form posts no value for the field at all, the widget is skipped and the field keeps its value.
  • Public methods whose names start with on are AJAX handlers. The widget's markup calls them by the widget's alias, as alias::onCheckTime, which getEventHandler('onCheckTime') returns.
php
<?php

namespace App\FormWidgets;

use Carbon\Carbon;
use Larajax\Ui\Classes\FormWidgetBase;

/**
 * TimeChecker is a custom form widget that compares the server clock with the browser clock and stamps the checked server time into its field.
 */
class TimeChecker extends FormWidgetBase
{
    /**
     * @var string format used to display the server times.
     */
    public $format = 'D j M Y, H:i:s T';

    /**
     * @var string defaultAlias to identify this widget.
     */
    protected $defaultAlias = 'timechecker';

    /**
     * init reads the display format from the field configuration.
     */
    public function init(): void
    {
        $this->fillFromConfig(['format']);
    }

    /**
     * loadAssets adds the widget stylesheet and script, served from the public folder.
     */
    protected function loadAssets(): void
    {
        $this->addCss('css/widgets/timechecker.css');
        $this->addJs('js/widgets/timechecker.js', ['defer' => true]);
    }

    /**
     * render the widget with its saved stamp.
     */
    public function render(): string
    {
        $this->prepareVars();

        return $this->makePartial('timechecker');
    }

    /**
     * prepareVars for the widget partials, where a checked server time replaces the saved stamp.
     */
    protected function prepareVars(?Carbon $serverTime = null): void
    {
        $stamp = $serverTime ?: $this->makeCarbon($this->getLoadValue());

        $this->vars['name'] = $this->getFieldName();
        $this->vars['value'] = $stamp ? $stamp->toDateTimeString() : '';
        $this->vars['stampLabel'] = $stamp ? $stamp->format($this->format) : null;
        $this->vars['serverTimeMs'] = $serverTime ? $serverTime->getTimestampMs() : null;
        $this->vars['isChecked'] = $serverTime !== null;
    }

    /**
     * onCheckTime reads the server clock and updates the widget, stamping the new time into the field.
     *
     * @return array<string, string>
     */
    public function onCheckTime(): array
    {
        $this->prepareVars(Carbon::now());

        return ['#'.$this->getId() => $this->makePartial('clock')];
    }

    /**
     * getSaveValue stores the stamped time, or null when the field holds none.
     */
    public function getSaveValue($value): ?string
    {
        return strlen((string) $value) ? (string) $value : null;
    }

    /**
     * makeCarbon converts a stored value into a date, ignoring values that do not parse.
     */
    protected function makeCarbon(mixed $value): ?Carbon
    {
        if (!$value) {
            return null;
        }

        try {
            return Carbon::parse($value);
        }
        catch (\Throwable $ex) {
            return null;
        }
    }
}

Partials ​

makePartial('timechecker') renders _timechecker.php from the partials folder beside the class, with $this as the widget and the entries of $this->vars as variables. A partial can render another one, as the outer partial does here.

The split matters for the handler. The outer partial keeps the element with the widget's id, which stays on the page, and the inner _clock partial is what goes inside it. The handler returns the inner partial keyed by # and that id, so Larajax replaces only the clock. The inner partial hides the check button in preview mode.

php
<div id="<?= $this->getId() ?>" class="time-checker-container">
    <?= $this->makePartial('clock') ?>
</div>
php
<div

    <?php if ($serverTimeMs): ?>data-server-time="<?= e($serverTimeMs) ?>"<?php endif ?>>
    <input
        type="hidden"
        name="<?= e($name) ?>"
        value="<?= e($value) ?>" />

    <dl class="time-checker-readings">
        <div class="time-checker-reading">
            <dt>
                Browser clock
            </dt>
            <dd data-timechecker-browser>
                --:--:--
            </dd>
        </div>
        <div class="time-checker-reading">
            <dt>
                <?= $isChecked ? 'Server clock' : 'Saved stamp' ?>
            </dt>
            <dd>
                <?= $stampLabel ? e($stampLabel) : 'Not checked yet' ?>
            </dd>
        </div>
        <div class="time-checker-reading">
            <dt>
                Drift
            </dt>
            <dd data-timechecker-drift>

</div>

The hidden input carries the stamp, named with getFieldName(), so the form posts it with the other fields and getSaveValue() receives it.

Registering the widget ​

registerFormWidget() gives the class a code, which fields name as their type. Register your widgets in a service provider's boot() method, through the widget manager's registerFormWidgets() callback. The provider also registers the list widget further down this page:

php
<?php

namespace App\Providers;

use Illuminate\Support\ServiceProvider;

class AppServiceProvider extends ServiceProvider
{
    /**
     * Register any application services.
     */
    public function register(): void
    {
        //
    }

    /**
     * Bootstrap any application services.
     */
    public function boot(): void
    {
        // The app's own form widget, used in field definitions as type: timechecker
        app('system.widgets')->registerFormWidgets(function ($manager) {
            $manager->registerFormWidget(\App\FormWidgets\TimeChecker::class, 'timechecker');
        });

        // The app's own list widget, used in column definitions as type: meter
        app('system.widgets')->registerListWidgets(function ($manager) {
            $manager->registerListWidget(\App\ListWidgets\Meter::class, 'meter');
        });
    }
}

Its own assets ​

loadAssets() runs when the widget is created, before init(), and adds the widget's files with addCss() and addJs(). Each takes a path and the attributes for its tag, such as ['defer' => true] or ['type' => 'module']. The path is resolved as follows:

  • a relative path, such as js/widgets/timechecker.js, is under public, so it is served from asset();
  • when the widget sets an $assetPath, relative paths are under that path instead, while a path starting with / stays under public;
  • a full URL, starting with https://, http:// or //, is used as it is.

The script registers a control, timechecker, that the markup starts with data-control="timechecker". The control reads the server time from data-server-time, which the partial sets after a check, ticks the browser clock, and works out the drift. Because the handler replaces the element, a new control starts for each check, and disconnect() stops the old one's timer.

js
/*
 * Time checker form widget
 *
 * Data attributes:
 * - data-control="timechecker" - ticks the browser clock and compares it with the checked server time
 * - data-server-time - the server time in milliseconds, present after a check
 *
 * The widget's AJAX handler replaces this element after each check, so a new control measures the new drift.
 */
'use strict';

(function () {
    jax.registerControl('timechecker', class extends jax.ControlBase {
        connect() {
            this.browserClock = this.element.querySelector('[data-timechecker-browser]');
            this.driftOutput = this.element.querySelector('[data-timechecker-drift]');

            if (this.config.serverTime) {
                this.showDrift(Date.now() - parseInt(this.config.serverTime, 10));
            }

            this.tick();
            this.timer = window.setInterval(this.proxy(this.tick), 1000);
        }

        disconnect() {
            window.clearInterval(this.timer);

            this.browserClock = null;
            this.driftOutput = null;
        }

        tick() {
            this.browserClock.textContent = new Date().toLocaleTimeString();
        }

        showDrift(driftMs) {
            const seconds = (driftMs / 1000).toFixed(2),
                isClose = Math.abs(driftMs) < 2000;

            this.driftOutput.textContent = (driftMs >= 0 ? '+' : '') + seconds + ' s';
            this.driftOutput.classList.toggle('is-close', isClose);
            this.driftOutput.classList.toggle('is-far', !isClose);
        }
    });
})();

Printing the assets ​

Ui::renderAssets() prints a <link> or <script> tag for every asset the widgets added during the request, stylesheets first and each file once. Call it in your layout's <head>, after the library's own assets. This works because Blade renders the page content before the layout around it, so by the time the head renders, the page's widgets have added their assets.

blade
<!DOCTYPE html>
<html lang="{{ str_replace('_', '-', app()->getLocale()) }}">
    <head>
        <meta charset="utf-8">
        <meta name="viewport" content="width=device-width, initial-scale=1">

        <title>
            @yield('title', 'Amber') - {{ config('app.name', 'Amber') }}
        </title>

        {{-- Sets data-bs-theme before the page paints, from the saved choice or else the OS preference --}}
        <script>
            (function () {
                var amberTheme = null;

                try {
                    amberTheme = localStorage.getItem('amber-theme');
                }
                catch (e) {
                    // Storage can be unavailable, so the OS preference applies
                }

                if (amberTheme !== 'light' && amberTheme !== 'dark') {
                    amberTheme = window.matchMedia('(prefers-color-scheme: dark)').matches ? 'dark' : 'light';
                }

                document.documentElement.setAttribute('data-bs-theme', amberTheme);
            })();
        </script>

        {{-- No build step: assets load from a CDN and the published vendor/larajax files. --}}
        <script src="https://cdn.jsdelivr.net/npm/@phosphor-icons/web@2.1.2"></script>
        <link href="https://cdn.jsdelivr.net/npm/bootstrap@6.0.0-alpha.1/dist/css/bootstrap.min.css" rel="stylesheet">
        <link href="https://cdn.jsdelivr.net/npm/bootstrap-icons@1.11.3/font/bootstrap-icons.min.css" rel="stylesheet">
        <link href="{{ asset('vendor/larajax/ui/ui.css') }}" rel="stylesheet">
        <link href="{{ asset('css/amber.css') }}" rel="stylesheet">
        <script type="module" src="https://cdn.jsdelivr.net/npm/bootstrap@6.0.0-alpha.1/dist/js/bootstrap.bundle.min.js"></script>
        <script src="{{ asset('vendor/larajax/framework-bundle.js') }}"></script>
        <script type="module" src="{{ asset('vendor/larajax/ui/ui.js') }}"></script>
        <script src="{{ asset('js/amber.js') }}" defer></script>
        <script type="module" src="{{ asset('js/code-blocks.js') }}"></script>

        {{-- Assets added by custom widgets; the page content renders before this layout, so its widgets are included --}}
        {{ Ui::renderAssets() }}
    </head>
    <body class="amber-layout">
        <div class="app-shell">
            <button
                class="sidebar-scrim"
                type="button"
                aria-label="Close navigation"
                data-amber-menu-close></button>

            @include('partials.site.sidebar')

            @include('partials.site.topbar')

            <main class="app-main">
                @yield('content')
            </main>
        </div>
    </body>
</html>

Ui::renderAssets('css') or Ui::renderAssets('js') prints one kind only, for a layout that places scripts at the end of the body.

A widget created by an AJAX handler, such as a form loaded into a popup, sends its assets with the handler's response instead, and the browser loads any that the page does not have yet.

A standalone widget ​

A widget does not have to be a form field. A standalone widget is built by a controller and printed in a view, the way the list, the filter and the form are. It suits a part of a page that has behaviour of its own and that more than one page can use, such as a feed, a panel or a picker.

The comment feed shows the newest comments on a post, three at a time, with a button that loads the next three. The controller builds it with make(), passing its options as named arguments:

php
<?php

namespace App\Controllers\Reference\ExtendingController;

use App\Models\Post;
use App\Widgets\CommentFeed;

/**
 * StandaloneWidgets builds the app's own widget on the Custom Widgets page.
 */
trait StandaloneWidgets
{
    /**
     * makeCommentFeedWidget builds the comment feed for the post with the most comments.
     */
    protected function makeCommentFeedWidget(): CommentFeed
    {
        $post = Post::query()->withCount('comments')->orderByDesc('comments_count')->first();

        return CommentFeed::make(
            post: $post ?? new Post,
            pageSize: 3,
        );
    }
}

The page's action passes the widget to its view, which prints it with . Three things follow from building it this way:

  • Nothing to register. A form widget needs a code because YAML names it. A standalone widget is built by its class, so the class is all there is.
  • Built in the action. make() binds the widget to the controller, which is how its handlers are reached. Build it in the action on every request, see built in the action.
  • Named by its alias. The alias is the class name in lower case, here commentfeed, so the handler is commentfeed::onLoadMore. Two feeds on one page need an alias each, passed as CommentFeed::make(alias: 'latestComments', ...).

The standalone widget class ​

A standalone widget extends Larajax\Ui\Classes\WidgetBase, the class that FormWidgetBase and the built-in widgets extend too. Everything the widget class says about init(), render(), handlers, partials and fillFromConfig() applies here. What a standalone widget leaves out is the field: it has no getLoadValue(), getFieldName() or getSaveValue(), and takes what it needs through its options instead.

php
<?php

namespace App\Widgets;

use App\Models\Post;
use Larajax\Ui\Classes\WidgetBase;

/**
 * CommentFeed is a custom widget that shows the newest comments on a post, a few at a time, and loads more through its own handler.
 */
class CommentFeed extends WidgetBase
{
    /**
     * @var Post|null post whose comments are shown.
     */
    public $post;

    /**
     * @var int pageSize is the number of comments shown at first, and the number each "Show more" adds.
     */
    public $pageSize = 3;

    /**
     * init reads the post and the page size from the options passed to make().
     */
    public function init(): void
    {
        $this->fillFromConfig(['post', 'pageSize']);
    }

    /**
     * loadAssets adds the widget stylesheet, served from the public folder.
     */
    protected function loadAssets(): void
    {
        $this->addCss('css/widgets/commentfeed.css');
    }

    /**
     * render the widget with its first page of comments.
     */
    public function render(): string
    {
        $this->prepareVars($this->pageSize);

        return $this->makePartial('commentfeed');
    }

    /**
     * prepareVars for the widget partials, with the given number of comments, newest first.
     */
    protected function prepareVars(int $shown): void
    {
        $total = $this->post->comments()->count();

        $this->vars['comments'] = $this->post->comments()->latest('id')->take($shown)->get();
        $this->vars['remaining'] = max(0, $total - $shown);
    }

    /**
     * onLoadMore adds a page to the comments already shown and updates the widget.
     *
     * @return array<string, string>
     */
    public function onLoadMore(): array
    {
        $this->prepareVars(max(0, request()->integer('shown')) + $this->pageSize);

        return ['#'.$this->getId() => $this->makePartial('comments')];
    }
}
  • init() copies the post and pageSize options onto the properties of the same name, keeping the property's value as the default.
  • render() prepares the first page of comments and returns the outer partial.
  • onLoadMore() reads the number of comments the page shows from the posted shown value, prepares that many and one more page, and returns the inner partial keyed by # and the widget's id, so Larajax replaces what is inside the widget's element.

The feed keeps nothing between requests. The button posts the number of comments shown, and Larajax runs the page's action again before the handler, so the handler works on the post the page was built with. A widget that has to remember something, as the search box remembers its term, can keep it in the session with putSession() and getSession().

The partials sit in a partials folder beside the class, in a folder named after it. The outer partial holds the element with the widget's id, and the inner one is what goes inside it, the same split the time checker uses:

php
<div id="<?= $this->getId() ?>" class="comment-feed">
    <?= $this->makePartial('comments') ?>
</div>
php
<?php if ($comments->isEmpty()): ?>
    <p class="comment-feed-empty">
        No comments yet.
    </p>
<?php else: ?>
    <ol class="comment-feed-list">
        <?php foreach ($comments as $comment): ?>
            <li class="comment-feed-item">
                <div class="comment-feed-meta">
                    <strong>
                        <?= e($comment->author) ?>
                    </strong>
                    <?php if ($comment->created_at): ?>
                        <time datetime="<?= e($comment->created_at->toIso8601String()) ?>">
                            <?= e($comment->created_at->diffForHumans()) ?>
                        </time>
                    <?php endif ?>
                </div>
                <p>
                    <?= e($comment->content) ?>
                </p>
            </li>
        <?php endforeach ?>
    </ol>
<?php endif ?>

<?php if ($remaining > 0): ?>
    <?= Ui::ajaxButton(
        label: "Show more ({$remaining} left)",
        handler: $this->getEventHandler('onLoadMore'),
        requestData: ['shown' => $comments->count()],
        icon: 'ph ph-caret-down',
        secondary: true
    ) ?>
<?php endif ?>

The button is a Ui::ajaxButton(). Its handler is the widget's own, from getEventHandler('onLoadMore'), and its requestData posts the number of comments shown. Everything a reader wrote goes through e(), since a partial is plain PHP and escapes nothing by itself.

The feed needs no script, only a stylesheet. loadAssets() adds it the way the time checker adds its own assets, and Ui::renderAssets() prints it:

        margin: 0;
        color: var(--bs-fg-3);
    }
}

A list widget ​

A list widget is a column type of your own. Where a partial column suits one list, a list widget is a class with options, partials, assets and AJAX handlers, so any list can name it as a column's type. The meter draws the views of each post as a bar, filled by its share of max, and clicking a bar names the views of that post:

yaml
columns:
    title:
        label: Title

    views:
        label: Views
        type: meter
        max: 8000
        sortable: true
php
<?php

namespace App\Controllers\Reference\ExtendingController;

use App\Models\Post;
use Larajax\Ui\Widgets\Lists;

/**
 * ListWidgetExamples builds the list that shows the app's own list widget on the Custom Widgets page.
 */
trait ListWidgetExamples
{
    /**
     * makeMeterList builds a list of posts whose views column is the app's meter list widget.
     */
    protected function makeMeterList(): Lists
    {
        return Lists::make(
            alias: 'meterList',
            model: new Post,
            columns: '~/resources/ui/reference/extending/custom-widgets/meter.yaml',
            recordsPerPage: 5,
            defaultSort: ['column' => 'views', 'direction' => 'desc'],
            customPageName: false,
        );
    }
}

The list makes one meter for the column when it defines its columns, which make() does as it binds the list, and asks the meter for each row's markup. The widget gets its code from registerListWidget(), inside the widget manager's registerListWidgets() callback, in the same service provider as the form widget.

A built-in column type keeps its code: a list widget registered as text or image is never used for those columns, and a code goes to the first widget registered under it.

The list widget class ​

A list widget extends Larajax\Ui\Classes\ListWidgetBase, a WidgetBase that knows its column.

php
<?php

namespace App\ListWidgets;

use Larajax\Classes\AjaxResponse;
use Larajax\Ui\Classes\ListWidgetBase;

/**
 * Meter is a custom list widget that draws a number as a bar, filled by its share of a maximum, and names the number when the bar is clicked.
 */
class Meter extends ListWidgetBase
{
    /**
     * @var int|float max is the value that fills the bar.
     */
    public $max = 100;

    /**
     * columnDefaults keeps the row link from taking clicks meant for the bar.
     */
    public static function columnDefaults(): array
    {
        return ['clickable' => false];
    }

    /**
     * init reads the maximum from the column definition.
     */
    public function init(): void
    {
        $this->fillFromConfig(['max']);
    }

    /**
     * loadAssets adds the widget stylesheet, served from the public folder.
     */
    protected function loadAssets(): void
    {
        $this->addCss('css/widgets/meter.css');
    }

    /**
     * renderValue draws the bar for a record's value, which the list passes in.
     */
    public function renderValue($record, $value): string
    {
        $value = (float) $value;

        return $this->makePartial('meter', [
            'key' => $record->getKey(),
            'value' => $value,
            'percent' => $this->getPercent($value),
        ]);
    }

    /**
     * onShowValue names the value of the clicked bar, finding its record through the list, so only a row the list shows answers.
     */
    public function onShowValue(): AjaxResponse
    {
        $record = $this->findRecord(request()->input('key'));

        if (!$record) {
            return ajax()->flash('error', 'That record is not in the list.');
        }

        $value = (float) $record->{$this->columnName};

        return ajax()->flash('info', $this->getColumn()->label.': '.number_format($value).', '.$this->getPercent($value).'% of '.number_format($this->max).'.');
    }

    /**
     * getPercent returns a value's share of the maximum, capped at 100.
     */
    protected function getPercent(float $value): int
    {
        return $this->max > 0 ? (int) min(100, round($value / $this->max * 100)) : 0;
    }
}
  • init() copies the column's options onto the properties of the same name, here max, as a form widget's init() does.
  • renderValue($record, $value) returns the markup of one cell, given the row's record and the column's value. The list calls it for every row, so the widget keeps nothing per row.
  • onShowValue() is an AJAX handler. The list binds its widgets to the controller when it defines its columns, so the handler is reached by the widget's alias, the list's alias and the column name, here meterListViews::onShowValue. getEventHandler() returns that name for the partial.
  • findRecord($key) finds the row's record through the list's own query, with its filters and search, so the handler cannot reach a record the list would not show. Post the record's key, not the record.
  • columnDefaults(), a static method, returns options a column of the type takes unless it sets them. The meter sets clickable: false, so a click on the bar does not follow the row link.
  • loadAssets() adds the stylesheet the first time a meter column renders.

getColumn() returns the column definition and getParentList() the list. A column hidden from the visitor by permissions has no widget, so its handlers cannot be reached. The partial receives the values renderValue() passes it:

php
<button
    type="button"
    class="list-meter"
    title="<?= e(number_format($value)) ?>"
    data-request="<?= e($this->getEventHandler('onShowValue')) ?>"
    data-request-data="<?= e(json_encode(['key' => $key])) ?>"
    data-request-flash="true"
>
    <span class="list-meter-bar" style="width: <?= $percent ?>%"></span>
</button>
